# Decision Arena — версия DEV (`/v2/`)

Рабочая версия 3D‑визуализации экономики токена Amber. По умолчанию запускается **симуляция**: 15 000 условных игроков и матчи 1 на 1. Включены все функции:

- чёрная дыра сжигания;
- «Найди себя» с «Моей историей», повтором пути и ползунком;
- машина времени;
- эпохи «Сейчас / Будущее»;
- карта мира;
- вид инвестора (план и факт);
- **песочница** с пометкой «модель, не прогноз»;
- турнир, минт гномов, майнинг;
- замки на астероидах (6 обликов, «Только с гномами»), коллекции замков ERC‑1155 с фильтром держателей;
- слой сети: ткань Polygon, кольца Chainlink и thirdweb (фабрика обликов с дропами), щит Electrum Decisions;
- пасхалка при максимальном отдалении: голова‑туманность с глазами и панель «Аудиты»;
- звук (по умолчанию выключен);
- режим киоска.

Переключатель «Симуляция / Блокчейн» в панели «Данные» переключает сцену на реальные данные Polygon. Источник тот же, что в `/live/`.

Как запустить: откройте `index.html` в браузере или выполните `python3 -m http.server` в папке `viz2` и откройте `http://localhost:8000/v2/`.

## Как подключить адреса контрактов

Все настройки лежат в одном блоке `window.ED_CONFIG`. Он общий для обеих версий:

- в исходниках это `src/a_cfg.html`;
- в готовом файле это первый `<script>` в `index.html`.

1. Откройте `src/a_cfg.html` и найдите раздел `contracts`.
2. Впишите адрес контракта (`0x…`, 42 символа) в поле `address` нужного контракта.
   - Пустая строка `''` означает, что контракт ещё не подключён. Сцена подписывает его «скоро».
3. Если знаете блок, в котором создан контракт, укажите его в `fromBlock`.
   - С этого блока начинается восстановление истории.
   - `0` — искать с начала.
4. Можно указать сигнатуры событий в `events` в формате Solidity, строкой или массивом. Например:
   `'endedGame(uint256 indexed id,address indexed winner,uint256 indexed amount)'`.
   - Без `events` контракт всё равно читается: по его балансу Amber и по переводам Amber на его адрес и с него.
5. Пересоберите файлы командой `./build.sh`. Она запишет `v2/index.html` и `live/index.html`.
   - Можно поправить блок `ED_CONFIG` прямо в готовом `index.html` и обойтись без сборки.

### Шахта и эпохи

- `contracts.mining.active: true` — майнинг запущен. Prod переходит в эпоху «Будущее»: шахта становится крупнейшим телом в центре, энергия идёт от неё к гномам.
- `contracts.mining.startBlock` — блок старта майнинга. Его можно не указывать. По нему машина времени показывает смену эпох.
- Пока майнинг не запущен, в prod кнопка эпохи включает только **предпросмотр**. Он отмечен меткой «предпросмотр».

### Юзернейм → адрес

- `usernameApi` — адрес игрового API, например `'https://api.example.com/user/{name}'`.
- Ожидаемый ответ: `{"address":"0x…"}`.
- Пусто — поиск работает только по адресу.

### Облик замка

- `skinResolver` в конфиге или `window.ED_skinResolver = addr => номер` снаружи.
- Функция получает адрес и возвращает номер облика:

| Номер | Облик |
|---|---|
| 0 | каменная крепость |
| 1 | ледяной шпиль |
| 2 | янтарная цитадель |
| 3 | деревянный форт |
| 4 | обсидиановый бастион |
| 5 | небесный храм |

- Без хука замки получают облик так:
  - в dev и демо облик выбирается детерминированно по адресу;
  - в prod на данных блокчейна всем ставится облик по умолчанию (0).

### RPC

- Список `network.rpcs` перебирается по порядку. При ошибке берётся следующий RPC.
- `maxRange` — сколько блоков запрашивать за один `eth_getLogs`.
- Если все RPC недоступны, появляется баннер «Не удалось связаться с публичными узлами Polygon». Сцена сама переходит на демо-данные, а кнопка «Повторить» снова пробует подключиться.

## Сцена: что где

- **Камень душ Amber** в центре: янтарный самоцвет с гранями. Это токен Amber.
- **Ткань пространства‑времени Polygon**: сетка под экосистемой, она прогибается под телами.
- **Туманность Chainlink** (синяя, #375BD2, без импульсов) — вспомогательная автоматизация, которая постоянно следит за контрактом стейкинга и при выполнении условий сообщает ему, кому и сколько выплатить, и запускает выплаты.
- **Оператор** — сервисный кошелёк студии, который вызывает `endGame` у контракта Battle (газ платит Оператор). На сцене и в карточках подписан «Оператор / Operator».
- **Кольцо thirdweb** (пурпурное) — **фабрика обликов**. NFT замков — один контракт ERC‑1155; token ID 0, 1, 2, 3… — это коллекции. Волна дропа теперь хорошо заметна: вспышка у кольца, ударное кольцо, яркие частицы со шлейфами, кольцо thirdweb на миг разгорается. Раз в 1–2 месяца (в симуляции — каждые 30–60 условных дней) из кольца вылетает волна дропа: лимитированные NFT замков летят в кошельки. Владельцы владеют ими и сами решают, что с ними делать. Цен нигде нет. В режиме блокчейна волна запускается только по реальным минтам.
- **Щит Electrum Decisions**: тонкий полупрозрачный эфирный пузырь с золотисто‑серебряным переливом и едва заметным шестиугольным узором. Он окружает экосистему между кольцами. По подписи «Electrum Decisions» открывается карточка.
- **Внешние площадки · скоро**: роялти **1% зашито в контракт NFT замков** — ровно 1%, изменить его нельзя. Оно платится с перепродаж NFT замков на внешних маркетплейсах (POL/USDC) и приходит в Банк Студии. Внутриигрового вторичного рынка нет и не будет. У гномов роялти нет.
- **Гномы (ERC‑721)**: лимит контракта 10 000, но #0 сожжён при минте и лежит на адресе 0x…dEaD, поэтому в обороте максимум **9 999**. В блокчейн‑режиме: «в обороте» = сминчено − сожжённые (на dead‑адресе), «не сминчено» = 10 000 − сминчено. Карточка кошелька показывает ID гномов, картинки из IPFS и ссылки на OpenSea. Описание из метаданных не показывается.

## Раскладка вселенной

- **Щит** (радиус 120) — почти прозрачная сфера: заметен только мягкий ободок по краю силуэта (эффект Френеля), шестиугольники едва видны у края и не перекрывают заголовок.
- **Внутренняя зона** у центра, разнесена по углу и радиусу: «Шахта · скоро» (≈ 10), **Боевой контракт** (пул матчей, ≈ 28) и **Гномы‑NFT** (≈ 37) вокруг Камня душ Amber.
- **Пояс астероидов** — толстый рассеянный «бублик» кошельков (радиус ≈ 44–101, основная масса ≈ 50–90; внешний край — ≈ 84 % радиуса щита). В поясе — только **игроки** (золотые звёзды, вблизи — замки). Трейдеры и боты живут снаружи щита у DEX (см. «Кошельки по поведению»).
- **Банк Студии** и **Стейкинг** — сразу снаружи пояса, но внутри щита (радиус ≈ 109–111). Чёрная дыра сжигания — ≈ 110.
- **Пул ликвидности DEX** — **снаружи щита** (радиус ≈ 140 при щите 120; «Внешние площадки» ≈ 137), примерно напротив чёрной дыры, рядом с «Внешними площадками · скоро». Потоки пула проходят сквозь щит.
- Подписи объектов не налезают друг на друга: при пересечении они мягко раздвигаются по вертикали.
- В «О проекте» есть тихая заметка: эта вселенная — ещё и визуальная модель мира будущей 4X‑игры (замки на астероидах); это только визуализация.

## Кошельки по поведению

Откуда создан кошелёк (игра создаёт некастодиальные кошельки thirdweb), по блокчейну не видно, поэтому класс определяется **только по поведению кошелька в сети**. Это написано и в легенде, и в карточке кошелька.

| Класс | Правило | Где на сцене |
|---|---|---|
| **Игроки** (золото) | любое действие в игре: взнос в пул матча, выплата, возврат взноса, стейкинг, турнир, гномы (минт или перевод гнома), Шахта | внутри щита в поясе; золотые звёзды, вблизи — замки (skinResolver без изменений) |
| **Трейдеры (только DEX)** (синие, #4F8DFF) | только покупка/продажа Amber через DEX или обычные переводы, без игры | снаружи щита: свободный рой на орбитах вокруг узла DEX (радиус ≈ 12–25 от DEX, ≥ 131 от центра) |
| **Связанные кошельки (игра + трейдинг)** (коралловые, #FF6A4D) | пара «игрок ↔ трейдер», между которыми был хотя бы один прямой перевод Amber. Только обычные кошельки: контракты (пул DEX, Battle, стейкинг, Банк, dead, гномы, роутеры) исключены. Кошельки‑распределители с более чем 5 такими связями не учитываются | оба кошелька коралловые; тонкая дуга между ними — при наведении/выборе или при фильтре «Кошельки: связанные» |
| **Торговые боты (по поведению)** (кислотно‑зелёные, #39FF14) | см. пороги ниже | плотный, быстрый, «дрожащий» рой прямо у DEX (≈ 9–13 от DEX) — вне экосистемы |

Агрегаторы и роутеры DEX (адреса, через которые Amber только проходит) — инфраструктура, а не кошельки: их не показываем и не считаем.

**Пороги ботов** (`BOT_T` в `e3_chain.js`), кошелёк — бот, если выполнено хотя бы одно:
- контракт (есть байткод, не EIP‑7702), который ≥ **3** раз покупал/продавал через пул;
- ≥ **150** сделок с DEX всего;
- ≥ **40** сделок за любые сутки (окно 43 200 блоков Polygon ≈ 24 ч);
- ≥ **3** «сэндвич»‑совпадений: покупка и продажа в одном или соседнем блоке;
- снайпинг: покупка в первые **2** блока после добавления ликвидности (событие `Mint` пары) ≥ **2** раз или в самом первом добавлении ликвидности (не для того, кто добавлял ликвидность).
Роутер: контракт, у которого ≥ 60 % из ≥ 3 транзакций — «вход и выход Amber в одной транзакции». Байткод адресов проверяется пакетами `eth_getCode` и кешируется в IndexedDB (`ed-cls-v1`); пока проверка идёт, счётчики помечены «…».

Нейтральная заметка в карточке бота: боты определяются только по поведению; они не часть экосистемы Decision Arena; DEX публичный, и повлиять на них мы не можем; метка описывает только поведение. Признаки (почему бот) показываются в карточке.

Интерфейс: легенда «Кошельки по поведению» (4 класса + «Связь: прямой перевод Amber»), счётчики классов в панели «Данные», кнопка‑фильтр «Кошельки: все / игроки / трейдеры / связанные / боты», карточка кошелька с классом, признаками и списком связанных кошельков (клик — перейти). Карточки трейдеров и ботов не показывают боевую статистику и замок. RU/EN.

В DEV (симуляция) пропорции правдоподобные: ≈ 77 % игроков, ≈ 23 % трейдеров, ≈ 3 % связанных, пара десятков ботов (при 15 000 кошельков: 11 528 / 3 449 / 468 в 234 парах / 23); по DEX летят частицы сделок трейдеров и ботов. В режиме «Блокчейн» применяются те же правила к реальным данным: игроки **738**, трейдеры (только DEX) **3 004**, торговые боты **51**, связанные кошельки **449** (пар **298**); агрегаторов/роутеров DEX скрыто и не посчитано — **145** (24.10.2026, ~05:05 по Таллину; 3 945 адресов, 133 948 переводов Amber).

## Матчи: сверка и ничьи

- Каждая завершённая игра порождает событие `EndGame`. Если победитель = `0x000…0000` — это **ничья**: оба взноса в пул матча **возвращаются полностью**, без сжигания, стейкинга и Банка (сплит 6/3/1 не применяется). В хранилище контракта для ничьей победителем записан Оператор.
- Панель «Данные» и карточка пула показывают сверку: **Создано = С победителем + Ничьей (возврат) + Отменено (+ Открыто, если есть)**.
- Ничьи на сцене — нейтральные серые потоки возврата взноса из пула обратно в оба кошелька (в легенде: «Ничья: возврат взноса обоим»).
- ID игры декодируется из topic события (например, `0x…1a76` → **#6774**, вызов `endGame` — селектор `0x86514131`).
- **Карточка кошелька**: сыграно матчей, победы, поражения, ничьи (возврат взноса), отменённые/не начатые (если есть), доля побед = победы / (победы + поражения + ничьи), доля побед и **итог в Amber по функции `getPnL` контракта** (в блокчейн‑режиме: «Итог в Amber (getPnL контракта)»; в симуляции — «Итог за всё время»). Отдельного итога «по переводам» больше нет. Ничьи и отмены дают 0. Только Amber, нейтральные формулировки.
- Источник в блокчейн‑режиме — проверенные view‑функции Battle (Sourcify): `totalStats(address)` (0x0be5f36f), `getAllDrawnOf(address)` (0x041a61f2; настоящие ничьи — `drawn` из totalStats включает и отменённые), `getPnL` (0xd89b7ec9).
- В симуляции ничьи ≈ 0,6 % матчей, отмены ≈ 19 %; сверка в панели выполняется так же. Кнопка «Начать заново» обнуляет и эти счётчики.

## Коллекции замков (ERC‑1155)

- Каждый token id — отдельная коллекция со своим цветом и обликом. Тираж фиксирован, примерно 10% от числа игроков.
- NFT замков — только косметика (плюс роялти 1% со вторичных продаж). Цен на сцене нет.
- Кнопка «Коллекции замков» открывает панель: выпущено/лимит, число держателей и кнопка «показать держателей» (фильтр астероидов по коллекции).
- На астероидах видны облики и флажки коллекций, которые есть у кошелька. В карточке кошелька есть строка с коллекциями.
- В симуляции коллекции — примеры, они подписаны «пример».
- Настройка — `contracts.castleNft`:
  - `address` — адрес ERC‑1155 контракта (thirdweb); пусто — панель пишет «скоро»;
  - `fromBlock` — с какого блока читать `TransferSingle`/`TransferBatch`;
  - `limits` — `{id: лимит}`, если контракт не отдаёт `maxTotalSupply(id)`;
  - `names` — `{id: 'название'}`, иначе название берётся из `uri(id)`;
  - `skinOf` — `{id: номер облика 0…5}`.

## Пасхалка: «за экосистемой наблюдают»

- Отдалите камеру до предела (колесо мыши или щипок). Внизу экрана есть едва заметная подсказка «отдалите камеру до предела…».
- За экосистемой проявляется колоссальная **голова из туманности** — только голова, без тела. У неё два глаза‑вихря: синие закручивающиеся потоки, звёздная пыль и золотой огненный ободок. Глаза медленно моргают и следят за курсором. Вся экосистема при этом выглядит крошечной на переднем плане.
- В зрачках — знаки аудиторов: в одном Token Sniffer, в другом SolidProof. Панель **«Аудиты»** открывается **только по клику/тапу** на глаз (или значки над глазами); при наведении — лишь курсор‑указатель и лёгкое свечение.
- Режим киоска раз в ~80 секунд сам отъезжает к глазам и возвращается.

### Настройка аудитов — `audits`

По слоту на контракт: `amber`, `battle`, `staking`, `bank`, `gnomeNft`, `dexPair`, `mine`, `tournament`, `castleNft`.

- Слот — массив отчётов `{auditor, url, date:'ГГГГ-ММ-ДД', scope, mechanicsSummary, checks:[]}`. Текстовые поля — строка или `{ru:'…', en:'…'}`.
- Пустой массив — «отчёт готовится». `'n/a'` — проверка не требуется (пул DEX — стандартный контракт пары).
- Студия закажет подробные отчёты по каждому контракту. Новые отчёты добавляются записью в нужный слот.

Сейчас в конфиге (каждая ссылка открыта и проверена 24.10.2026):

| Контракт | Проверки |
|---|---|
| Amber | Аудит SolidProof (страница проекта указывает AmberSoulStone.sol по адресу Amber), Token Sniffer, Sourcify (full match) |
| Battle, Staking, NFT гномов | Sourcify (full match) |
| Банк, шахта, турниры, NFT замков | отчёт готовится |
| Пул DEX | н/д |

SolidProof работал со студией над проверкой контрактов (включая ещё не выпущенную шахту) и безопасной настройкой автоматизации вместе с Chainlink.

- `index.html` — один самодостаточный файл. three.js 0.160.0 грузится с jsdelivr через importmap. Нужен только интернет, сервер не нужен. Можно открыть файл напрямую или положить на любой статический хостинг.
- `shots/` — скриншоты из автотеста. Новые в этом раунде: `23_linked_pair_selected.png` (выбран связанный кошелёк, линия к паре), `24_dex_traders_swarm.png` (рой трейдеров у DEX, фильтр «трейдеры»), `25_overview_classes.png` (общий вид: игроки под щитом, рой у DEX), `26_dex_bots_traders.png` (боты и трейдеры у DEX крупно).
- Исходники лежат в `../src/`, сборка — `../build.sh` (порядок файлов задан в скрипте явно).

Все цифры и сцены иллюстративны. Курса Amber в долларах и прогнозов здесь нет.
